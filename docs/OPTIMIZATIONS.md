# 六项结构与性能优化

以下六项是发布门槛，不是未来路线图；对应实现与回归测试必须随产品一起维护。

| 优先级 | 调整 | 已落地机制 | 验证 |
| --- | --- | --- | --- |
| P0 | 防幻觉答案闭环 | 当前事实先取官方/网页证据；Claim 必须引用本轮 source_id 与来源原文片段；结构不合格只重写一次，仍失败就拒答 | `test_answer_validation.py`、`test_turn_orchestrator.py` |
| P0 | 能力边界与等待体验 | 播歌等未实现能力由确定性规则拦截；删除随机有语义的预置过渡语音，只保留延迟出现的中性文字 | `test_android_assets.py`、`test_turn_orchestrator.py` |
| P1 | 长驻连接与安全抓取 | ASR、搜索、答案和 TTS 共用有界 HTTP 连接池；每次重定向在访问前重新校验 HTTPS、域名和公网地址 | Provider、官方来源和网页检索测试 |
| P1 | 明确单轮状态与并发 | 转写、检索、校验、合成、播放、打断和失败由状态机约束；转写与历史上下文读取并发 | `test_turn_state.py` 与 WebSocket 集成测试 |
| P1 | 模块化与供应商可替换 | ASR、Search、Answer、TTS 使用 Protocol 接口；发布 API/制品校验从主应用拆到 `api/` 与 `services/` | mypy、API 发布与下载测试 |
| P2 | 量化门槛与同制品发布 | 至少 50 题盲评准确率、完成率、无证据声明和 P50/P95；同一个签名 APK 先 Beta 后 Stable，晋升不重编译 | `check_performance_budget.py`、发布通道测试 |

## 过渡提示策略

回答内容在 ASR 完成前未知，因此客户端不得随机播放“我去查最新资料”“这个谜语很有趣”等带
语义的录音。当前策略为：2.2 秒内完全安静；超过 2.2 秒只显示中性的“我想一想…”；首个回答
音频、打断、完成、断线或错误都会立即取消提示。未来即使重新加入声音，也只能使用不表达问题
类型的短提示音，并必须允许家长关闭；默认仍为无过渡语音。

## 证据风险分级

- 稳定知识：不要求预登记官方来源，允许模型用稳定基础知识简短回答。
- 一般时效、商品价格与参数：没有预登记官方来源时，可由联网搜索发现页面；服务器独立抓取、
  校验并在需要时交叉印证后放行。
- 医疗用药、法律、金融交易、选举和现任政治职位：必须取得预登记官方证据，或命中政府、公共
  卫生机构等权威域名的已抓取证据。只有普通媒体或商业网页时继续拒答。
- 现实中的着火、自伤等紧急安全问题不等待联网检索，直接给出简短的安全行动和求助建议。
